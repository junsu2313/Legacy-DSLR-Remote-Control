# 선행 기반 작업 — 세션 유지·복구 우선 구조 · 1.0 Alpha

버전: 1.0 Alpha  
상태: 오팔 실기 검증 완료 프로토타입 / 제품 릴리스 아님

현재 구현은 실제 장비에서 기본 복구 흐름을 확인한 프로토타입이다.
장시간 반복 운용과 다양한 장애 조건을 검증하기 전에는 제품 릴리스로 승격하지 않는다.

웹 사용 중에는 기존 세션을 유지하고 자동 복구한다.
브라우저 프로세스가 완전히 종료되어 새 명령 세션을 부팅할 때는 이전 라이브 세션,
프레임 캐시, 모드 파일을 재활용하지 않고 깨끗하게 초기화한다.

## 목표

일시적인 브리지, WebSocket, PTP, 워커 장애가 발생해도 기존 세션을 먼저
유지하고 내부 구성요소만 복구한다. 세션 재생성은 마지막 수단으로 제한한다.

## 복구 우선순위

1. 현재 세션과 라이브 세션의 정체성을 유지한다.
2. 죽은 워커·WebSocket·브리지만 개별적으로 재시작한다.
3. PTP 연결이 잠시 흔들리면 재시도와 상태 재확인을 수행한다.
4. 락·큐·임시 플래그·캐시를 정리하고 같은 세션에서 재개한다.
5. 위 방법으로도 세션을 복구할 수 없을 때만 세션 재생성을 실행한다.

## 세션 재생성 조건

- PTP 세션 자체가 유효하지 않다고 확인된 경우
- 카메라 재연결 또는 USB 재연결이 발생한 경우
- 복구 재시도 한도를 초과한 경우
- 세션 상태와 실제 카메라 상태를 더 이상 일치시킬 수 없는 경우

단순한 프레임 지연, 단일 명령 실패, WebSocket 재시작, 워커 종료만으로는
세션을 새로 만들지 않는다.

## 검증 기준

- UI 새로고침 없이 브리지 장애 후 기존 세션으로 복귀
- UI 새로고침 없이 WebSocket 장애 후 기존 세션으로 복귀
- 단일 명령 실패 후 같은 세션에서 다음 명령 실행
- 복구 중 라이브 세션 생산자를 교체하지 않음
- 세션 재생성은 명시된 최후 조건에서만 발생
