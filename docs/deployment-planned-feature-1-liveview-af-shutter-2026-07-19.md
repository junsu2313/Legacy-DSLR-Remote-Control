# 개발 예정 기능 2 — 라이브뷰 유지형 AF·셔터 · 1.0 Alpha

버전: 1.0 Alpha  
상태: 오팔 실기 검증 완료 프로토타입 / 제품 릴리스 아님

현재 구현은 실제 D810에서 라이브뷰·AF·SHOT 기본 동작을 확인한 프로토타입이다.
장기 실사용 검증 전에는 제품 기능으로 간주하지 않는다.

## 목표

라이브뷰를 끄지 않은 상태에서 사용자가 화면으로 초점 지점을 확인하고,
AF와 셔터를 각각 독립적으로 실행할 수 있게 한다.

## 동작 계약

1. 라이브뷰 세션은 계속 프레임을 수신하고 표시한다.
2. AF 버튼은 AF만 실행하며 셔터를 자동으로 실행하지 않는다.
3. SHOT 버튼은 사용자가 별도로 눌렀을 때만 셔터를 실행한다.
4. AF와 SHOT은 명령 세션에서 독립적으로 요청할 수 있다.
5. 카메라로 들어가는 실제 PTP 명령은 공용 카메라 큐에서 직렬화한다.
6. 사용자가 AF 후 SHOT을 누른 경우에만 AF 결과를 확인한 뒤 SHOT을 처리한다.
   AF 요청 자체가 SHOT을 예약하거나 실행하지는 않는다.
7. AF 중 들어온 프레임은 표시를 위해 계속 흐르며, 명령 완료를 기다리느라
   프레임 생산자를 새로 만들거나 라이브 세션을 교체하지 않는다.
8. `Device Busy`, `AF 불가`, `세션 미준비`, `AF 성공`은 서로 다른 결과로 UI에 전달한다.

## 현재와의 차이

현재 배포본은 AF·SHOT 전에 라이브뷰를 종료하는 안전 경로를 사용한다.
이 기능은 라이브뷰 스트림과 카메라 명령 전송을 분리하되 카메라 장치 접근
지점만 짧게 직렬화하는 방식으로 바꾼다.

여기서 “동시에 동작”한다는 의미는 AF 버튼이 셔터를 자동 실행한다는 뜻이
아니다. 라이브뷰가 계속 흐르는 동안 AF를 실행할 수 있고, 셔터는 별도의
사용자 입력으로만 실행할 수 있다는 뜻이다.

## 테스트 및 배포 규칙

- 카메라 없이 로컬 mock/fault 테스트를 먼저 만든다.
- 라이브뷰 중 AF, AF 완료 후 별도 SHOT, AF 실패 후 SHOT 처리 정책을 검증한다.
- 실제 카메라에서 반복 검증한 뒤에만 Opal에 배포한다.
- 이 문서의 상태가 `배포 가능`으로 바뀌기 전에는 Opal 파일을 변경하지 않는다.
